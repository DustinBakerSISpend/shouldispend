# ShouldISpend Working Rules

## Safety and Git
- Inspect before editing.
- Use PowerShell syntax for shell commands.
- Never use `git add .`.
- Do not stage, commit, push, deploy, delete files, or modify Git history unless explicitly instructed.
- Keep changes narrowly scoped to the requested task.
- Do not make opportunistic or unrelated cleanup changes.
- Show the exact changed files and a concise diff summary before stopping.

## Builds and Commands
- Avoid unnecessary builds because builds are slow and may trigger deployment usage.
- Do not run `npm run build` unless explicitly instructed.
- Prefer the narrowest relevant audit or validation command.
- Report every command run and whether it passed.

## Current Product Direction
- ShouldISpend is in an AdSense quality-remediation phase.
- Do not create new calculators until that restriction is explicitly lifted.
- Current priorities are substantive topic depth, calculator UX, result placement, worked examples, assumptions, risks, internal linking, trust signals, and selective sourcing.
- Do not substitute bulk or formulaic text for useful page-specific content.

## Calculator and Editorial Rules
- Take-home income means income after taxes.
- Results measure financial pressure; they do not grant permission or provide personalized professional advice.
- Preserve factual assumptions, limitations, ownership, and review information.
- Distinguish necessary expenses from optional upgrades.
- Do not change formulas, routes, redirects, metadata, indexing, noindex status, or sitemap behavior unless the task explicitly requires it.
- Preserve deliberate noindex pages unless specifically instructed otherwise.

## Working Style
- Work on one bounded task at a time.
- Clearly separate confirmed findings from recommendations.
- Ask before making a broad architectural change.
- Stop after completing and validating the requested scope.
